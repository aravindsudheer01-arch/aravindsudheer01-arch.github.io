# Aravind Sudheer — engineering, software and data portfolio

**Live website:** https://aravindsudheer01-arch.github.io/

The site presents **Projects**, **Experience** and **About**, followed by a contact footer with email, GitHub and LinkedIn links. No separate CV page or public CV PDFs are needed. Projects are technical case studies (including selected employer-related projects); Experience describes professional roles, responsibilities and achievements.

## Development

Edit content in `content/`, pages in `templates/`, images in `assets/images/` and the appearance in `assets/style.css`. Do **not** edit generated HTML in `dist/`. To preview locally from a clone:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python build.py
python scripts/check_site.py
python serve.py
```

Visit http://localhost:8000. The workflow in `.github/workflows/deploy.yml` runs checks and publishes the rebuilt site after a push to `main`.

## Add photographs, screenshots and videos

Keep the existing explanatory SVGs until real project media has been approved. For new photos or screenshots, save an optimized JPG/PNG/WebP to `assets/images/` and edit the relevant case-study YAML file under `content/projects/`. You can replace the project's `image`, `image_alt`, and `image_caption`, or create a `gallery`:

```yaml
gallery:
  - src: assets/images/robot-assembly.webp
    alt: Assembled robot mechanism on a workbench
    caption: Physical assembly photographed during testing
```

For video, use a real HTTPS link to an approved, externally hosted demonstration in the `demo_url` field. Project pages already display it as an **Open project demo** link. Video files are not yet stored or embedded in the site.

Do not upload confidential employer/client materials, API secrets, unconsented face videos, or personal addresses. Clearly distinguish real photos from diagrams and label testing limitations.

## Site and content files

- `content/profile.json`: professional background, contact links and credentials
- `content/projects/*.md`: ten case studies and their media metadata
- `templates/`: page layouts, navigation and reusable project cards
- `assets/`: styles, scripts and illustrations
- `tests/` and `scripts/check_site.py`: build and link verification
- `CONTENT_REVIEW.md`: evidence and publication policy
- `DEPLOY.md`: live deployment instructions
- `review/`: **historical** QA reports from an earlier site version, including retired CV checks

The project is a static site generated by Python, Jinja2 and Mistune. No analytics, remote fonts, visitor database or contact-form backend are required.
